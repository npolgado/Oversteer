# Oversteer Code Review (2026-03-22)

Scope: post-modularization review. The codebase was split from a single `arena-drifter/index.html` (~4600 lines) into 9 JS modules. This review covers the refactor quality, the EventLog migration (replacing floating texts), the resolution change, and lingering issues from the 2026-03-11 review.

## What's Working Well

- **Clean module decomposition.** The 9-file split follows natural system boundaries (logic / audio / fx / input / physics / entities / world / waves / game). Load order is respected via `<script>` tags and all inter-module refs are `window.*` accessed at call-time — no circular dependency issues.
- **EventLog is a UX improvement.** Replacing world-space floating texts with a screen-anchored HUD panel makes events readable at all camera distances, especially during fast drift sequences. Migration is complete — no remaining `Particles.addFloat` or `renderFloats` calls anywhere in the codebase.
- **Floating text removal is clean.** The `floatingTexts` array, `addFloat()`, `renderFloats()`, and the associated update loop were all removed from `fx.js`. No dead references remain in any module.
- **Prior P0 blockers are resolved.** Mobile menu start, mobile upgrade selection, Speed Demon split, Trail upgrade persistence, and menu prompt all appear fixed per the 2026-03-11 review.

## Blockers / P0 Issues

- **EventLog panel background ignores entry count fade.**
  - `EventLog.render()` (`fx.js:467`) draws a single opaque background panel for all entries at once, but each entry fades individually.
  - Impact: the panel background stays fully opaque after entries start to fade, creating a dark rectangle with invisible/ghost text. Visually broken in the final ~1.3s of each entry's life.
  - Fix: either fade the background with the oldest entry's alpha, or render each entry with its own mini-background pill, or clip the background to only non-fading entries.

- **EventLog panel width is fixed at `S(110)` regardless of text length.**
  - `fx.js:470`: `ctx.roundRect(x, panelY, S(110), ...)`. Text is drawn with `size: 11` and up to ~20 characters (e.g. "STREAK x3! +750"). At 1600×900, `S(110)` ≈ 96px which clips longer entries.
  - Impact: streak/encircle messages like "ENCIRCLE x5! +pts" are truncated.
  - Fix: measure text width with `ctx.measureText()` before drawing, or increase the fixed width to `S(140)`.

## Performance Issues

- **`EventLog.update` uses `.splice()` for removal** (`fx.js:452`).
  - The coding convention (CLAUDE.md) requires swap-and-pop instead of `.filter()` or `.splice()` on per-frame arrays.
  - Impact: negligible at max 7 entries, but inconsistent with the project's own GC-pressure guidance.
  - Fix: iterate backward (already done) and use swap-and-pop: `this.entries[i] = this.entries[this.entries.length - 1]; this.entries.pop();`. Alternatively, since display order matters, accept `.splice()` with a comment noting max 7 entries.

- **Chain lightning still uses `.filter()` on the enemies array** (`world.js:399`).
  - `const killed = enemies.filter(e => !e.alive)` runs inside the encirclement path (every 0.15s).
  - Impact: allocates a new array on every encirclement event. Acceptable today but inconsistent with the project convention.
  - Fix: inline a manual scan with a counter or pre-allocated scratch array.

- **`Props.checkNearMiss` still iterates `allProps` flat list** (`world.js:143`).
  - This was flagged in the 2026-03-11 review. The chunk grid is correctly used for collision (`checkPlayerCollision`) but not for near-miss.
  - Impact: scales linearly with world-visible prop count; visible on large worlds or high-density maps.
  - Fix: mirror the chunk-based approach from `checkPlayerCollision`.

## UX / Consistency Issues

- **EventLog `render()` always draws panel even when all entries are near-invisible.**
  - The background panel is drawn whenever `this.entries.length > 0`, including entries at 99% fade. This leaves a faint dark box on screen after events.
  - Fix: skip rendering (or skip background) if all entries have alpha below ~0.05.

- **Resolution changed to 1600×900 without CLAUDE.md update.**
  - `logic.js:4` now sets `CFG.W = 1600, CFG.H = 900` (was 1920×1080). The UI scale factor `S()` uses reference `1280×720`, so the effective `S()` multiplier is now `1.25` (was `1.5`). All UI elements are ~17% smaller.
  - `index.html:37-38` correctly uses `CFG.W`/`CFG.H` for canvas sizing, so there is no mismatch.
  - Impact: aesthetic only — UI/text may feel slightly small on large monitors. Not a bug.
  - Action: Update CLAUDE.md to reflect the new resolution.

- **`speedRush` / `doubleEnemies` still mutate CFG directly** (`game.js:383-396`).
  - Previously flagged as known debt in MEMORY.md. Still present and fragile — relies on `applyMap()` resetting `CFG_BASE` first.
  - No urgency, but worth addressing before adding more difficulty modifiers.

## Maintainability / Architecture Notes

- **`window.*` cross-module coupling is workable but untyped.**
  - Every module does `const X = window.X` inside functions to get peer modules. This is late-binding (safe) but a typo is a silent `undefined` at runtime. 9 modules × ~5 peer references = ~45 implicit contracts.
  - Not a bug today, but as the game grows this pattern will cause hard-to-trace errors.
  - Suggestion: add a one-time startup assert in `index.html`'s bootstrap (e.g. `['CFG','Audio','FXCache','Particles','ScreenFX','Camera','EventLog','Input','Assets','updatePhysics','Player','Enemy','enemyDeathFX','Props','Trail','Waves','ARENA_UPGRADES','STATE','Game'].forEach(k => { if (!window[k]) throw new Error('Missing: ' + k); });`) to catch missing exports immediately on load.

- **Load order is implicit (script tag order), not declared.**
  - If a module is accidentally reordered in `index.html`, the failure won't be detected until the missing peer is called. The startup assert above would catch this.

- **`CLAUDE.md` project docs are out of date post-refactor.**
  - The "Source of truth" and "Project Structure" sections still describe the game as a single `index.html`. This will mislead contributors and AI agents.
  - Fix: update CLAUDE.md (being done as part of this review action).
