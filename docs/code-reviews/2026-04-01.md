## Additional Review Findings

The staged phase 1 additions expose several user-facing behaviors that do not match the original game or the roadmap: one map renders incorrectly, one upgrade is over-offered, and multiple upgrade cards currently do nothing. Those regressions make the patch incomplete from a gameplay-correctness standpoint.

- [P2] Exclude Auto Repair once the third stack is owned
  File: `src/gameplay/upgrades/upgradeSystem.ts:22-25`
  After the player has already taken `hp_regen` three times, `buildUpgradeOffer()` still leaves `hp_regen` in the pool. The original upgrade logic caps Auto Repair at 3 stacks, so in long runs this patch can keep offering it indefinitely and lets regen scale past the intended balance.

- [P2] Apply Speed Demon enemy speed bonus when the upgrade is picked
  File: `src/gameplay/upgrades/upgradeRegistry.ts:63-64`
  `speed_demon` is advertised as `+20% speed, enemies +10% speed`, but this implementation only mutates the player. Enemy spawns still read only `waveState.speedBonus` in `GameplayScene`, and nothing increments that when this upgrade is applied, so picking Speed Demon makes enemies slower than intended relative to the original game.

- [P2] Load the selected map background instead of hard-coding City Boys
  File: `src/scenes/gameplayScene.ts:252`
  When the player selects `arena_02`, `applyMap()` updates `CFG.BACKGROUND_SPRITE`, but gameplay always loads `Assets.get('background_01')` here. That makes the new map-select flow render Loopy with the wrong background, so the selected map is only partially applied.

- [P2] Wire Trail Burn into gameplay before exposing the upgrade
  File: `src/gameplay/upgrades/upgradeRegistry.ts:113-114`
  Selecting `trail_burn` only flips `player.trailBurn`, but no gameplay code in this patch ever reads that flag. In the original game, enemies touching the trail take periodic damage; here the card is a no-op, so players can spend an upgrade choice on an effect that never triggers.

- [P2] Trigger Chain Lightning during encirclement kills
  File: `src/gameplay/upgrades/upgradeRegistry.ts:117-118`
  `chain_lightning` is also only stored as a flag and never consumed when a loop kill resolves. The original implementation chains each encirclement kill to a nearby enemy, but the current `updateTrail()` / `GameplayScene` kill path removes enemies without any follow-up damage, so this upgrade currently has no effect.
