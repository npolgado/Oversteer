## Finding 1 — Bounce asymmetry: player vs enemy (balance bug)

**File:** `src/gameplay/world/propsSystem.ts:166, 202`

Player prop collision applies `0.3` multiplier; enemy collision applies `0.4`. `CFG.BOUNCE_RETAIN = 0.35` exists but neither path uses it.

Per CLAUDE.md TS-port rule: *"Symmetric behaviors use the same CFG key."* Both sides of a symmetric bounce should reference the same constant, or intentional asymmetry should be documented.

**Fix:** Use `CFG.BOUNCE_RETAIN` (or add `CFG.ENEMY_BOUNCE_RETAIN`) in both handlers. If asymmetry is intentional for gameplay feel, add a comment.

## Finding 2 — Combo heal description doesn't reflect new cap (clarity)

**File:** `src/gameplay/upgrades/upgradeRegistry.ts:98`

Combo heal description says `"3/5/8"` — the actual milestones in `pureLogic.ts:499`. These are still correct but the cap raised from 8→16 in M11 means the phrasing is misleading: the upgrade description implies the cap is 8 when the actual run behavior allows combos up to 16.

## Finding 3 — Per-frame `.filter()` in minion spawn path (performance)

**File:** `src/scenes/gameLoop.ts` — `_spawnMinionRing()` method

The method calls `.filter()` to count current chaser enemies on the array before spawning each minion ring. This is O(n) on the full enemies array and runs during boss combat every time Core spawns a minion ring.

Per CLAUDE.md: *"avoid `.filter()` on per-frame arrays — swap-and-pop."*

**Fix:** Maintain a `_minionCount` counter incremented on spawn and decremented on death, or scan the count once per ring spawn call and pass it in rather than re-filtering each invocation.

## Finding 4 — Splitter score gate silently interacts with biome bias (design gap)

**File:** `src/gameplay/pureLogic.ts:316` + `src/gameplay/spawning/waveManager.ts:265`

`getEnemyPool(score)` gates splitter into the pool at `score >= 3500`. Biome bias (`_buildWeightedPool`) then multiplies weight — but if biome bias sets `splitter: 6` before score 3500, the type isn't in the base pool so the bias has no effect. Conversely, once splitter is in the pool, biome weight of 0 (not currently used) would still leave 1 copy due to `Math.max(1, ...)` in `_buildWeightedPool:170`.

This is a latent design gap, not a current bug. No biome currently sets `splitter: 0`.

**Fix (low priority):** Add a comment at `_buildWeightedPool` explaining that `Math.max(1, ...)` prevents complete removal of score-gated types. If future biomes need to suppress a type, the floor must change.

## Finding 5 — Duplicate purchase logic in shopPanel (code debt)

**File:** `src/ui/menus/shopPanel.ts:196–215, 241–246`

`tryPurchase()` in the pointer click path and the identical block in `handleGamepadInput()` share no common helper. Affordability check, effect application, and scrap deduction are duplicated. Not a functional bug (input paths are mutually exclusive per frame), but a maintenance risk — updating purchase logic must happen in both places.

**Fix:** Extract purchase logic to a `_executePurchase(item, player)` private method used by both paths.
